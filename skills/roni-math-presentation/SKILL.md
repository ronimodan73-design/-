# מצגת מתמטיקה — מורה שנייה על המסך

**Teach first. Visualize second. Animate third.**

המצגת לא מסכמת שיעור. היא מלמדת אותו. תלמיד צריך לחשוב **יחד** איתה, לא לצפות בה.
המבחן היחיד: מורה פותחת את הקובץ, נכנסת לכיתה, ומלמדת — בלי הכנה נוספת.

## 0. איפה הסקיל הזה יושב

| סקיל | מה הוא נותן | היחס |
|---|---|---|

| `wow-presentation-design` | שכבת עיצוב-על | רץ יחד; אם העיצוב מתנגש בפדגוגיה — הפדגוגיה מנצחת |

## 1. הכלל שאי אפשר לעקוף

> לעולם אל תציג חוק, נוסחה, פתרון או מסקנה שלמים אם אפשר לבנות אותם בהדרגה.

הרצף הקבוע:
**Observe → Predict → Think → Reveal → Explain → Generalize → Practice**

זה אומר, בפועל:
- הנוסחה מופיעה **אחרי** שהרעיון הובן, לא לפני.
- התשובה אף פעם לא על אותה שקופית עם השאלה.
- פתרון תרגיל נחשף שלב-שלב, עם נימוק לכל שלב, ובדיקה בסוף.
- אם התלמיד לא הספיק לנחש — חשפת מוקדם מדי.

דוגמה: `(a+b)²` לא נכתב בהתחלה. בונים ריבוע, מחלקים לשטחים, מדגישים כל חלק,
שואלים למה שני חלקים יצאו זהים — ורק אז כותבים את הנוסחה.
המימוש המלא של הדוגמה הזו נמצא ב-`assets/example_deck.js` והוא נקודת ההתחלה לכל דק חדש.

## 2. תהליך העבודה

### שלב א׳ — ארבע שאלות (לשאול, לא לנחש)
כיתה ושכבה · הנושא ומה כבר נלמד לפניו · אורך השיעור · על מה מקרינים.
אם התשובה ידועה מהשיחה — ממשיכים בלי לשאול שוב.

### שלב ב׳ — סטוריבורד לפני קוד
טבלה, שורה לכל שקופית: `# | תפקיד | שורת המסר | ויזואל | Teacher Action | Student Thinking`.
**מציגים את הסטוריבורד לרוני ומחכים לאישור.** זה חוסך בנייה מחדש של 30 שקופיות.
המבנה המלא (19 תפקידי שקופית, מפתיחה עד Exit Ticket) — `reference/pedagogy.md`.
אין מספר שקופיות קבוע: איכות ההוראה קובעת, לא מכסה.

### שלב ג׳ — בנייה
`npm install pptxgenjs` בתיקיית העבודה (פעם אחת), ואז דק לפי `assets/example_deck.js`:

```js
const path = require("path");
const SKILL = path.join(process.env.HOME, ".claude/skills/roni-math-presentation");
const { buildDeck, T } = require(path.join(SKILL, "scripts/deck_kit.js"));

buildDeck({
  file: "ז_שיעור_03_מערכת_צירים",
  outDir: "out",
  slides: [{
    role: "התבוננות → ניחוש",
    teacher: "מצביעה על הצלע ושואלת: מה השטח? אל תחשבו — נחשו.",   // חובה
    student: "מנחשים בקול. חלק ינחשו a²+b² — וזה בדיוק מה שרצינו.", // חובה
    seconds: 6,                                   // כמה זמן להחזיק ב-MP4
    base(s, k) { k.kicker(s, "התבוננות"); k.title(s, "מה שטח הריבוע?");
                 k.areaModel(s, { a: 3, b: 2, show: ["frame", "dims"] }); },
    layers: [                                     // כל שכבה = לחיצה אחת
      { effect: "wipeRight", seconds: 5,
        draw(s, k) { k.areaModel(s, { a: 3, b: 2, show: ["aa", "labels"] }); } },
    ],
  }],
});
```

שקופית בלי `teacher` ו-`student` לא נבנית — הקיט זורק שגיאה.
**זה מכוון**: לשקופית בלי תפקיד פדגוגי אין מקום במצגת.
כל ה-API — `reference/build.md`.

### שלב ד׳ — שלושת התוצרים
ספק אחד מייצר את שלושתם, כך שהם לא יכולים להתפצל:

```bash
node deck.js                                     # → out/<שם>.pptx  + <שם>__build.pptx + timing
python3 $SKILL/scripts/add_animations.py out/<שם>.pptx --report      # אנימציות אמיתיות
python3 $SKILL/scripts/render.py out/<שם>__build.pptx \
        --pdf out/<שם>.pdf --mp4 out/<שם>.mp4 --timing out/<שם>__timing.json
```

- **PPTX** — המצגת הראשית, ניתנת לעריכה, עם אנימציות לחיצה אמיתיות.
- **MP4** — נבנה מגרסת ה-build, ולכן שומר את קצב החשיפה. וידאו מהמצגת המונפשת
  היה מראה את כל השכבות יחד והורס את כל הרעיון.
- **PDF** — גיבוי להדפסה. **אינו תחליף למצגת** כשהאנימציה היא חלק מההוראה.

### שלב ה׳ — QA לפני מסירה
```bash
python3 $SKILL/scripts/qa.py out/<שם>.pptx --anim
```
בודק אוטומטית: bidi שבור, טקסט שחורג מהשקופית, פונט לא בטוח, טקסט קטן מדי,
שקופית עמוסה, שקופית בלי הערות מורה, משקל הקובץ.
**זה החצי המכני בלבד.** הצ׳ק-ליסט הפדגוגי — `reference/qa.md` — נשאר באחריותך,
וכולל את השאלה היחידה שחשובה: האם משהו נחשף מוקדם מדי?

## 3. אנימציה היא פדגוגיה, לא קישוט

לפני כל אנימציה: **מה אני רוצה שהתלמיד יבין ברגע הזה?** אין תשובה — אין אנימציה.

| מתי | אפקט |
|---|---|
| חלק חדש בציור, שטח, קטע | `wipeRight` / `wipeUp` — התנועה עצמה מספרת מה נוסף |
| טקסט עברי שנחשף | `wipeLeft` (מימין לשמאל — כיוון הקריאה) |
| שורה, שלב פתרון, מסקנה | `fade` |
| הדגשה של מה שמדברים עליו עכשיו | מלבן `k.highlight` שנכנס ב-`fade` |
| תוצאה סופית | `zoom` — ובחיסכון |
| שני דברים שחייבים להופיע יחד | `"fade:withPrev"` |

`appear`, `fade` ו-`wipe` עוברים נקי בין PowerPoint, LibreOffice, Google Slides
ו-Keynote. `zoom` מתדרדר ל-appear ב-LibreOffice — מותר, אבל לא בונים עליו הבנה.
אין אפקטים שדורשים תוכנה מיוחדת, אין plugins, אין מאקרו.

בפתרון תרגיל הרצף קבוע: שאלה → זמן לחשיבה → שלב 1 → הסבר → שלב 2 → הסבר → תוצאה → בדיקה.

אם אי אפשר להנפיש — בונים build-slides עוקבות שמדמות בדיוק את אותו רצף.
**לעולם לא מוותרים על בנייה הדרגתית בגלל מגבלה טכנית.** (הקיט מייצר את שתיהן ממילא.)

## 4. עומס קוגניטיבי — התאמה לחטיבה ולקשיי קשב

מוקד חזותי אחד בכל רגע. מעט טקסט. כותרות קצרות. רווח גדול.
מדגישים את מה שמדברים עליו עכשיו ומסתירים את מה שעדיין לא נחוץ.
**עדיף 3 שקופיות פשוטות מאשר שקופית אחת צפופה** — `qa.py` נכשל על צפיפות, לא מזהיר.
טקסט גדול מספיק לקריאה מהשורה האחורית. פסקאות — לא. איור + שאלה קצרה — כן.

## 5. עברית ומתמטיקה באותה שקופית

טקסט, כותרות, רשימות, טבלאות וניווט — RTL אמיתי.
מספרים, ביטויים, משוואות, נוסחאות, גרפים ומערכת צירים — כיוון מתמטי תקין.
**אין להפוך נוסחה בגלל RTL.**

טכנית: כל מחרוזת שמערבת עברית עם ספרה או אות לטינית עוברת דרך `k.pmx()`;
ביטוי מתמטי טהור עובר דרך `k.ltr()`. הקיט עושה את זה בכל ה-helpers שלו.
מחרוזת ידנית ש-`addText` מקבל ישירות — באחריותך. `qa.py` תופס את זה ונכשל.
הרקע המלא: `hebrew-math-notation`.

## 6. עיצוב

Apple-inspired: נקי, רגוע, מדויק, פרימיום. הרבה whitespace, היררכיה ברורה,
טיפוגרפיה גדולה, **צבע דגש אחד**, רכיבים עקבים.
אסור: rainbow design, ריבוי צבעים, צללים כבדים, גרדיאנטים, אייקונים מיותרים,
כרטיסיות בכל מקום, קישוט שלא תומך בלמידה.
מושג שקיבל צבע — שומר עליו לאורך כל המצגת (`T.color.c1..c4`).
הפירוט: `reference/design.md`.

קובץ אחד, עצמאי: בלי קבצים חיצוניים, בלי פונטים נדירים (Arial בלבד), בלי plugins,
בלי תלות בתיקייה מקומית, בלי קישורים שבורים, בלי אלמנטים שנעלמים במחשב אחר.
תמונות דחוסות, בלי רזולוציות מיותרות, בלי assets שאינם בשימוש.
